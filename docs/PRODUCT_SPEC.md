```

## 페이지 구조

하나의 반응형 페이지에 다음 순서로 표시한다.

1. 상단 소개
2. 가수·곡명 검색창
3. 카테고리 필터
4. 결과 개수와 초기화 버튼
5. 노래 카드 목록
6. 상태 및 하단 안내

검색이나 필터 사용 시 다른 페이지로 이동하지 않고
현재 페이지의 노래 목록만 즉시 갱신한다.

## 상단 문구

제목:

`베베리 노래책`

설명:

`가수 또는 곡명으로 노래를 검색해보세요`

## 검색

검색창 placeholder:

`가수 또는 곡명을 검색하세요`

- 입력 즉시 검색 결과를 갱신한다.
- 가수와 곡명을 함께 검색한다.
- 부분 문자열 검색을 지원한다.
- 대소문자를 구분하지 않는다.
- 한글, 영어, 일본어를 지원한다.

## 카테고리 필터

API에서 받은 `categories` 배열로 버튼을 생성한다.

- 카테고리를 여러 개 선택할 수 있다.
- 선택한 카테고리끼리는 OR 조건이다.
- 검색어와 카테고리 조건 사이는 AND 조건이다.
- 선택한 카테고리를 다시 누르면 선택을 해제한다.
- 전체 버튼은 모든 카테고리 선택을 해제한다.
- 카테고리는 정확한 문자열 값으로 비교한다.
- `POP` 선택 시 `K-POP`, `J-POP`이 포함되면 안 된다.
- 선택 버튼에는 `aria-pressed`를 적용한다.

필터 논리:

```javascript
matchesText && matchesAnySelectedCategory
```

카테고리를 선택하지 않은 경우 모든 카테고리를 허용한다.

## 결과 표시

초기 상태:

`전체 120곡`

검색어 또는 카테고리 적용 상태:

`검색 결과 24곡`

초기화 버튼을 누르면 다음을 모두 초기화한다.

- 검색어
- 선택된 카테고리
- 검색 결과

## 노래 카드

카드 표시 순서:

1. 가수
2. 곡명
3. 카테고리 칩

예:

```text
아이유
무릎
[K-POP] [발라드]
```

- 가수는 먼저 표시한다.
- 곡명은 가수보다 조금 크게 표시한다.
- 카드 전체를 링크나 버튼으로 만들지 않는다.
- 긴 가수명과 곡명은 줄바꿈한다.
- 모바일에서는 1열, 넓은 PC에서는 2열로 표시한다.

## 상태 화면

로딩:

`노래 목록을 불러오는 중이에요…`

검색 결과 없음:

`검색 결과가 없습니다.`

`가수, 곡명 또는 선택한 카테고리를 다시 확인해주세요.`

오류:

`노래 목록을 불러오지 못했습니다.`

`잠시 후 다시 시도해주세요.`

오류 화면에는 `다시 불러오기` 버튼을 제공한다.

## 프런트엔드 데이터

홈페이지는 `./data/songs.json`을 `cache: 'no-store'`로 요청한다.
방문자의 브라우저에서는 Apps Script API를 직접 호출하지 않는다.
검색과 필터는 최초 로드한 데이터를 브라우저 메모리에서 처리한다.

## 파일 구조

```text
index.html
css/style.css
js/app.js
data/songs.json
apps-script/Code.gs
README.md
```

`apps-script/Code.gs`는 Google Apps Script에 배포한 코드의
보관 및 유지보수용 사본으로 사용한다.

## 첫 구현 범위

- `data/songs.json` 운영 데이터 모드
- 가수·곡명 실시간 검색
- 카테고리 다중 선택
- 다중 카테고리 OR 필터
- 검색어와 카테고리 AND 결합
- 카테고리 정확 일치
- 결과 개수
- 전체 초기화
- 모바일·PC 반응형
- 로딩·오류·검색 결과 없음
- GitHub Pages 배포 안내 README

1차 구현에서는 다음 기능을 만들지 않는다.

- 즐겨찾기
- 노래 신청
- 관리자 페이지
- 로그인
- 시트 수정
- localStorage 캐시
